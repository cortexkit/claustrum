# KEM recipient slice: source reconnaissance

This is a snapshot of the pre-open vault contract. Source symbols below are the
anchors for the route and migration work; a route-level test is needed wherever a
new operation changes the observed behavior. The operator's authenticated
`admin.store` and `admin.store_with_identity_policy` accept a typed `VaultRecord`
(`admin_ops::AdminOpBody`, `admin_ops::apply`); they are deposit authority, not
read authority. They deliberately retain their ability to deposit a `KemKey`.
The two `ReadSurface` payload fences now block its disclosure instead.

| Contract | Source symbols and observed behavior | Named pin |
|---|---|---|
| Base64 | `ReadSurface::sign` decodes via `base64::engine::general_purpose::STANDARD`: RFC 4648 standard alphabet, canonical padding, strict trailing-bit decoding. This existing sign path currently maps decode failure to `SignPayloadTooLarge`, not `invalid_params`; open must supply its own malformed-input mapping. | `kem::tests::signing_decoder_uses_padded_strict_standard_base64` pins the sign-site engine and accepted/rejected padding; open-specific decoding pin belongs with the route. |
| Handle limiter | `ReadSurface::check_limiter` invokes `FetchLimiter::admit(connection_id, probe_key, Instant::now())` before handle resolution. `FetchLimiter::admit` (`limiter.rs`) counts **all presentations**, not only failures, by connection id, retaining a window-scoped set of distinct presented handles and a timestamp per request. `DEFAULT_DISTINCT_CEILING = 16`, `DEFAULT_RATE_CEILING = 64`, `DEFAULT_WINDOW = 60s`; `ConnState::prune` resets after the rolling window empties and `drop_connection` clears connection state. First threshold crossing appends one `FetchAnomaly` audit alarm; it does **not** refuse or delay the wire request. `resolve_key_address`'s scoped arm bypasses this limiter. `FetchLimiter::admit` accepts an explicit `Instant`, a reusable test clock. | `limiter::tests` pins admission/window; `key_exercise_handle_sweeps_run_the_limiter` pins the handle call site. Open needs a separate failures-only, connection-keyed gate and a recovery test. |
| Error classes | `read_surface::ErrorClass` and `ERROR_CLASS_WIRE_SET` carry `transient`, `permanent`, `auth_required`, `context_overflow`; `ReadError::class` maps `SignPayloadTooLarge` to `context_overflow` and `KindNotGettable` to `permanent`. | `the_wire_contract_doc_names_every_error_class`, `error_class_wire_strings_match_pinned_set`. |
| Key container | `signing::parse_pkcs8_pem` is private and uses `ring::signature::Ed25519KeyPair::from_pkcs8_maybe_unchecked`: it accepts Ed25519 PKCS#8 v1/v2, **not** X25519 OID 1.3.101.110. `kem::parse_pkcs8_pem` instead requires X25519 RFC 8410 PKCS#8 v1 PEM; a different armour or algorithm is named in its diagnostic. | `kem::tests::a_wrong_container_names_what_was_found`; `signing::tests::a_pkcs8_v1_seed_key_signs_and_matches_its_published_public_half`. |
| Public key id | `signing::key_id_for_public(public: &[u8]) -> String` takes raw public bytes and returns lowercase hex of the first 8 bytes of SHA-256. It was private; now public to `kem::public_half`. `signing::public_key_ed25519` and `signing::sign_ed25519` both use it. `ReadSurface::public_key` scopes via **Read**, not Sign. | `existing_ed25519_key_id_is_byte_identical`; `kem::tests::generated_recipient_opens_two_fresh_sequence_zero_requests`. |
| Frame and payload bounds | `main::handle_route_request` receives frames through `subc_transport::read_frame`; this crate does not set an additional frame cap on the operation. The open route must verify the effective transport cap before deciding whether to add a pre-decode encoded-length bound. `signing::MAX_SIGN_PAYLOAD = 1024 * 1024`; `ReadError::SignPayloadTooLarge` serializes `sign_payload_too_large`. | `signing::tests::the_signing_cap_refuses_one_byte_over_and_accepts_the_cap`; `read_error_classification_table`. |
| Migration 10 | `store::MIGRATIONS` version 10 rebuilds `read_grants_v10` then renames it to `read_grants`: `principal_kind TEXT NOT NULL CHECK IN ('reserved','enrolled')`, `principal_id TEXT NOT NULL`, `selector_kind TEXT NOT NULL CHECK IN ('exact','category')`, `selector TEXT NOT NULL`, `operation TEXT NOT NULL CHECK IN ('read','sign')`, `created_at_ms INTEGER NOT NULL`, PK `(principal_kind,principal_id,selector_kind,selector,operation)`. Source includes no `read_grants` index, trigger, or FK naming the table; its automatic SQLite PK index is the one associated sqlite_master object. It copies from the Rust-prepared `migration_10_grant_plan`, which migration 11 must not reuse. `grants_generation` is seeded at `(1,1)` and grant/category mutations increment it. | Store's migration-10 tests under `store::tests` and `newest_migration_version`; migration-11 conservation must be pinned in slice 2. |
| Schema-10 pins | `store::SELECTOR_SCHEMA_VERSION = 10`, `store::MIGRATIONS` v10 and `newest_migration_version`; `store::read_grants_from_conn` chooses selector columns by that constant; `EncryptedStore::migrate_inner` uses v10 as the threshold for its migration plan. The schema-10 assumption appears in `docs/anthropic-auth-enrollment-migration.md` and in the `store::tests` DDL-equivalence fixture (`schema_version_of` asserted 10; fresh schema-10 store). The wire-contract v1 document names migration 10's category backfill and grant selector change; `docs/operator-runbook.md` explains rollback/store-ahead compatibility. | Store DDL-equivalence test comparing `vault_schema_objects` of upgraded and fresh databases; fixture schema version assertion 10. |
| Scoped first use | `EncryptedStore::record_scoped_first_use` inserts into `auth_events` (not the audit chain), idempotent by credential, principal kind/id and operation; operation is stored in unconstrained `detail` text, so adding `open` requires no auth_events CHECK change. `ReadSurface::authorize_scoped_as` calls it after authorization. | `scoped_get_reveals_signing_kind_only_after_read_grant`; route's first-open idempotence pin belongs in slice 3. |
| Grants | `GrantOperation::FromStr` rejects with `unknown grant operation '{value}' (expected read or sign)`. `credentials_cli::parse_grants` validates `read|sign`; CLI operation argument parsing and admin-op serde parse likewise currently accept the existing vocabulary. `admin_ops::apply` Status calls `store.list_read_grants`, backed by `read_grants_from_conn`, and `admin_ops::status_result` renders grant rows. `EncryptedStore::list_scoped_snapshot_inner` includes a row when its operations set is nonempty: a Sign-only grant **does** yield a row, without decrypting the payload or identity. | `get_many_delegates_signing_key_refusal_without_blocking_other_items`; grant/parser pins belong in slice 2/3. |
| Read custody | `ReadSurface::get` resolves a handle first; `get_many` invokes `get` for each item. `get_scoped` calls `authorize_scoped_as` with Read before loading the record and checking kind. Both get fences now use `CredentialKind::is_vault_held_key`; an ungranted and an unknown scoped id have identical `not_found` replies, while granted reads refuse `kind_not_gettable`. `sign` resolves through `resolve_key_address` using Sign before its `!= SigningKey` fence. `public_key` uses Read before its own `!= SigningKey` fence. | `kem_key_payload_is_absent_from_get_get_many_and_get_scoped` (both fences mutation-tested); `scoped_get_reveals_signing_kind_only_after_read_grant`. |
| Payload outputs | Route `credential.get` (`ReadSurface::get`) and `credential.get_many` (`ReadSurface::get_many` -> `get`) and `credential.get_scoped` (`ReadSurface::get_scoped`) can emit `GetResult.payload`: now refuse KemKey. `credential.sign`, `credential.public_key`, `credential.status`, `credential.list_scoped`, `auth.enroll_*`, `admin.status` emit no stored credential payload (`SignResult`, `PublicKeyResult`, `StatusResult`, `ListScopedResult`, `admin_ops::status_result`). The `ck auth` verb dispatch (`credentials_cli::run`) has no `get`, `get-scoped`, `export`, `dump`, or plaintext-backup verb. `ck auth list`/`status`/`grants` read metadata, and the `vault_read_probe` example prints payload length rather than payload bytes. Store backup is a SQLite copy of sealed `credentials.envelope`, restored by opening/migrating the copied store with its matching vault master key (`EncryptedStore::migrate`); it never emits plaintext credential payload. | `kem_key_payload_is_absent_from_get_get_many_and_get_scoped`; route/CLI inventory pins for all surfaces remain future work. |
| Gate | `scripts/gate.sh::run_expect` sums `test result: ok. N passed` counters and compares the sum against numeric floors; its workspace unit/integration floor begins at 724. This is a count of tests, **not** mutation-evidence entries. A floor raise belongs to the final measured full-suite change. | Gate's own count-floor checks (single exception: floor is not a Rust test). |

Published crypto conformance fixture: `crates/credentials-core/tests/fixtures/rfc9180-a2-base.json`
is the mode=0, KEM=32, KDF=1, AEAD=3 entry from
<https://github.com/cfrg/draft-irtf-cfrg-hpke/blob/master/test-vectors.json>,
the source of RFC 9180 Appendix A vectors. `kem::tests::rfc9180_a2_opens_every_published_encryption_in_one_context`
checks all **257** published sequence positions 0 through 256 in one retained
receiver context (including 0, 1, 2, 4, 255, 256); no random round trip can
substitute for this check.
